# From direction to a moment worth remembering

Use this for autonomous creation and expressive lift across the eight scenario classes. Establish viewer change and the through-line with [director pre-production method](director-method.md) first, then use the methods below to find the more expressive option. A simple task records only the key choices and needs no separate set of files; a complex task expands along the [direction template](../templates/direction.md).

## Autonomous work must leave checkable judgement

Within this run's authorization, facts, immutable assets and resources, the agent researches, compares, chooses and pushes ahead; when the user has not asked for a direction review, do not stop and wait item by item. State each requirement as "action → decision or artifact → basis → how to verify → adjustment if it fails to hold"; these can be folded into the existing plan or notes, and five separate files are not mandatory.

Separate what the material states outright, what is interpretive inference and what is creative metaphor, then settle the theme, the viewer change and the key turn. A metaphor must not pose as the author's intent, a news fact or a product capability; existing work can serve as a starting point without locking the new direction.

## A reference must be able to name the gap

Name the unsolved creative problem first, then choose relevant work, the user's existing assets or the audience's context. Research should close a specific gap such as "how to make the relationship visible" or "which composition suits this emotion"; stop searching once the judgement has enough basis. Check current discussion only when present-day context matters — do not chase every trend by default.

Each reference card records:

| Item | What to record |
| --- | --- |
| Source and scope | The original entry point, version or file, and the time range actually observed; note separately whether you only read source, pulled frames, watched continuously or auditioned |
| Expressive purpose | What that segment makes the viewer notice, understand or feel |
| Observation evidence | Which specific action, composition or sound-image relation supports the judgement; keep the source's own account separate from what you saw yourself |
| Transferable relation | For example "give the whole first, then push in on the evidence along the same object"; state the relation before choosing the technique |
| Current gap | Which shot's information is unclear, where the energy does not change, where consequence or handoff is missing; never write only "not elevated enough" |
| How to verify | Which state should be readable, where continuity should hold, which actual viewing or listening comparison can decide; if you have not checked it, record it as pending |

Thumbnails, frame differences or waveforms help you find cut points and candidate problems; go back to full-size clips and the actual sound to confirm. You cannot derive "best in class" from source code, finished-file properties or the author's claim. Extract the principle; do not copy the source's layout, imagery, characters, music or brand.

## Compare directions, state the aesthetic boundary

A complex open task may compare a few substantively different directions, choose among them on relevance, audience, distinctiveness, real implementation capability and resources, and record the trade-off. A style name should let you derive the approach to composition, light, material, type, motion and sound; a coined term alone is not enough. Two or three options are not a fixed requirement.

Write "feeling you want → visible/audible choices → observable failure → corrective action". For a light, clear product feel, for example, check whether a busy background hides the result and whether the UI chime overrides the explanation, then simplify and change the timbre to match the problem; never write only "premium" or "no AI look". Check shot by shot against this film's boundary, and allow contrast and variation where there is a reason.

For an unknown capability, judge from the current documentation and a minimal test per [shot production planning](shot-production.md). Do not lower the creative ambition in advance out of unfamiliarity, and do not claim tool support out of optimism. Keep novelty, distribution ambition and proven effect apart; never promise a hit.

## Describe the key event before choosing the effect

Propose one to three moments worth remembering, scaled to the task. Start without effect names: write "what it was before → what happens → what it is after → what the viewer gains from it". Only when the directions differ substantively and the choice affects the whole film, offer a few alternatives with your reason for choosing; three options first or a stop-and-wait are not fixed requirements.

A product film, for example: "Three scattered requests go into the same task entry, the processed results return to their own places, and the viewer sees how one operation completes the whole task." That is only an expressive idea; where the real product does not support the flow, change it to a task you have evidence for — animation must not manufacture capability.

Tie each moment to an existing shot, story beat, key entity and real basis, and state the before and after state, the visual focus, the sound's job and the handoff to the next shot. Record it in the direction text or the existing director plan; that prose is not a new executable field, so do not reshape the plan contract on your own.

## Let the motif change with the content

The recurring object can be a request card, a word, light, a shape, a spatial relation or a sound motif. Each appearance should advance the meaning: from problem to operation, from operation to result, or from unfamiliar to familiar. Repeating only colour and decoration cannot carry a through-line.

A handoff can run through position, scale, direction, shape, eyeline or sound. When the join must be seamless, check the subject, coordinates, velocity and occlusion on both sides of the cut point; a semantic turn may also use an explicit switch, silence or a hold. A fixed stage helps comparison and a repeating layout can establish a rule; do not break comprehension for the sake of change.

## Primary motion and secondary response

Pick the single most important event in the shot, then stagger the remaining motion by cause and effect. Try the order below, then cut it back to fit the content:

| Stage | Directorial judgement |
| --- | --- |
| Preparation | Has the viewer already found the object of the action; is the anticipation necessary |
| Primary motion | Who changes what; does the camera or the subject carry the main motion |
| Secondary response | How labels, background and followers respond; avoid every layer starting and stopping together |
| Settle and reading | The result, the copy and the spatial relation have enough time to be seen clearly |
| Exit and handoff | How the next shot catches the information, direction or sound; how the tail and the occlusion end |

For the same attribute in the same time span, name a single owner; do not let scene animation and camera fight over position or scale at once. Choose easing, springs, arcs and motion blur by material, scale and expressive purpose; not every interface has to bounce and not every entrance has to accelerate. Stillness can serve reading and emotion, and micro-motion must not cost the type its stability.

## Sound or image leads the beat — the content decides

When voiceover leads, measure the real lines first; when a music performance leads, fix the sections and accents first; when a product demo leads, lock the trigger, feedback and result first. They share semantic events, which then land on the existing absolute time and source-asset time — do not build a competing clock. Primary and secondary motion and the sound may be deliberately offset, but only with an expressive reason and an actual check. See [sound and rhythm](sound-and-rhythm.md).

Check the audio alone or a rough mix of the key passage first, then check cause and attention against the picture; when you cannot actually listen back, leave the listening gap explicit and do not call it comfortable just because the plan is written. Full music, local sound effects and silence are all available; a whoosh on every cut is not a rule.

## Creative type and production choice

| Type of the reference prompt | How to use it in the existing scenarios |
| --- | --- |
| showreel | Craft or a visual motif leads; music-visual or brand-film may fit; organise around a core idea that develops |
| product | A product task leads; use product-demo or feature-motion, and real operations need visible consequences |
| launch-story | Use story-video when there is a human event; for a product launch choose by purpose between product-demo and brand-film |
| explainer | knowledge-explainer for knowledge, news-brief for an event update; settle one main relation first |

These four are direction descriptions only: they add no scenario ID and do not replace `plan.mode`'s recipe/compose/free. Given images can still follow image-story. The user's request, brand constraints and actual facts decide the trade-off; do not turn a reference prompt into a mandatory rule of the kit.

Code production can provide editable components and deterministic timing; screenshots, screen recording, generated frames and an existing project each have tasks they suit. Choose the route that best preserves fidelity and delivers the intent; do not force code to rebuild every asset or rule out generated frames. Production specs, asset versions, the short sample clip and aspect-ratio fitting are handled in [runtime and delivery](runtime-and-delivery.md).

## Key expression must be delivered in the cut

Tie the important changes the through-line promises to existing scene/element/beat and to real passages: a product's trigger and result, knowledge's condition and causality, a story's action and consequence, a brand motif's development, music's sections and release. For each key point write the expected change, the actual sound-image basis and what was not delivered; where you hold back on purpose, give the reason. Not every beat needs an effect, and a reversal in every film is not required.

## Compare, revise, stop

Put the key moment back against the reference card's specific goal and check whether the gap closed. Fix the biggest problem affecting fact, comprehension, reading, listening or continuity first, then the decoration. Record the review per [review and revision](review-and-revision.md) with time points, evidence, the revision and the recheck, separating an independent review from self-review.

Before you start, write the exploration limit and the stop condition from the user's scope, the risk and the resources. Deliver once the required acceptance is met; if the resource limit arrives first, keep the best real version, the unmet goals and the reason, do not loop forever, and never write "checks ran" as an aesthetic pass.
